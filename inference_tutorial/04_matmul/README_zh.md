> 目标：实现 `W (d,n) @ x (n,) -> xout (d,)`。模型 99% 的时间都花在这一个函数里。

## 背景

一次前向传播中，所有线性投影都归结为同一个矩阵-向量乘法：

- 注意力：`wq`、`wk`、`wv`、`wo`
- FFN：`w1`、`w2`、`w3`
- 输出层：分类器 `wcls`（与 embedding 共享权重）

llama2.c 中该函数的签名约定是 `matmul(out, x, w)`：**输出在前，其次是输入向量，权重矩阵最后**。每次调用把当前激活 `x`（长度 n）通过权重矩阵 `w`（形状 (d,n)，行优先）投影成输出 `out`（长度 d）。之所以是"权重行 ↔ 输出维"而不是反过来：checkpoint 里的每个权重张量按 (out_dim, in_dim) 存储，第 i 行存放产生第 i 个输出分量的全部权重——点积时这一行在内存中是连续的，对缓存和带宽最友好。

## 数学原理

W 按行优先存储，共 d 行，每行 n 个 float：

```
xout_i = sum_j  W[i*n + j] * x[j]        i = 0..d-1
```

即 W 的第 i 行与 x 做点积得到 `xout_i`。在本模块的玩具例子里 d=3、n=4；在真实模型里它们是 (288, 288)、(768, 288)、(288, 768)、(32000, 288) 这样的尺寸。

## 常见错误

- 输出顺序错乱 → 行列弄反了：`w[i*n + j]` 是第 i **行**第 j 列，第 i 行对应 `xout[i]`。
- 与 expected 有系统性偏差 → 累加和用了 `double`；请用 `float` 累加以匹配参考实现。
- 正确性只是入场券，重点是**性能**：每个权重元素只参与一次乘加，工作量与读取字节数成正比，是典型的内存带宽受限任务。可以比较 `-O2` 与 `-O0`，或尝试用多线程并行外层循环；模块 12 的 int8 版本将读取字节数降至 1/4，这就是 decode 加速的全部秘密。
